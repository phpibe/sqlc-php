Changelog

A PHP code generator inspired by sqlc. Write annotated SQL, get fully-typed PHP 8.3+ classes backed by PDO — no ORM, no query builder, no magic.

PHP 8.3+ PDO MySQL 8+ Fully typed No ORM

How it works

schema.sql + queries.sql + sqlc.yaml
  ↓
php vendor/bin/sqlc-php sqlc.yaml
  ↓
User.php + UserQuery.php + UserQueryInterface.php

sqlc-php reads your SQL schema and annotated query files, resolves column types against the schema, and generates three kinds of files per query group: a Model (readonly class hydrated from PDO rows), a Query class (one method per query), and an Interface for dependency injection.

Requirements

DependencyVersion
PHP≥ 8.3
PDO extensionEnabled (default)
symfony/yaml^6.0 || ^7.0 || ^8.0
doctrine/inflector^2.0 (pluralization)

Installation

composer require phpibe/sqlc-php

Create a sqlc.yaml config file, annotate your queries, then run:

php vendor/bin/sqlc-php sqlc.yaml

Configuration — sqlc.yaml

All configuration lives in a single YAML file. Below is the full annotated reference:

version: "2"

# ── Schema ──────────────────────────────────────────────────────────────────
schema:
  - database/schema/users.sql          # one or more CREATE TABLE files
  - database/schema/orders.sql

# ── Global defaults (overridable per target) ─────────────────────────────────
engine:        mysql                   # mysql (postgres planned)
language:      english                 # inflection language for model names
class_suffix:  Query                   # e.g. Repository → UserRepository
                                       #       Service    → UserService

# ── Global type overrides ────────────────────────────────────────────────────
type_overrides:
  - db_type:  "TINYINT"
    php_type: "bool"

# ── Database connection (for --generate-schema) ──────────────────────────────
database:
  dsn:      "mysql:host=localhost;dbname=myapp;charset=utf8mb4"
  username: "${DB_USER}"               # ${ENV_VAR} expanded at runtime
  password: "${DB_PASS}"
  exclude_tables: [migrations, failed_jobs, sessions]
  # include_tables: [users, orders]    # whitelist — only these tables
  exclude_views:  [v_legacy]           # skip specific views
  # include_views: [v_active_users]    # whitelist views

# ── Shared CTEs (available to all targets) ───────────────────────────────────
ctes:
  - database/ctes/users.sql
  - database/ctes/orders.sql

# ── Virtual tables (views, materialized views, CTEs) ────────────────────────
virtual_tables:
  - name: user_summary
    columns:
      - { name: id,    type: INT }
      - { name: email, type: VARCHAR }
      - { name: total, type: INT }

# ── Includes (split config across files) ─────────────────────────────────────
includes:
  - config/shared.yaml

# ── Output targets ───────────────────────────────────────────────────────────
targets:
  - namespace: "App\\Database"
    out: generated/                    # string form: all files in one dir
    queries:
      - database/queries/users.sql
      - database/queries/orders.sql
    generate_interfaces:      true     # generate *Interface.php (default: true)
    prepared_statement_cache: false    # cache PDOStatement objects (default: false)
    class_suffix:  Query               # per-target override
    engine:        mysql
    language:      english
    type_overrides:
      - db_type: "DECIMAL"
        php_type: "float"
    ctes:                              # per-target CTEs (merged with global)
      - database/ctes/billing.sql
    scoped_dtos: false                 # put DTOs in same namespace as queries

type_overrides

Override the default SQL → PHP mapping globally or per-target. Useful for treating TINYINT as bool, or using Carbon instead of DateTimeImmutable.

type_overrides:
  - db_type:  "TINYINT"
    php_type: "bool"

  - db_type:  "DATETIME"
    php_type: "\\Carbon\\Carbon"       # use Carbon for all datetime columns

  # Narrow to a specific table and column
  - db_type:  "DECIMAL"
    php_type: "float"
    table:    "products"
    column:   "price"
Per-target type_overrides are merged with global overrides — per-target takes precedence when the same db_type appears in both.

--generate-schema

Connects to a live MySQL database and writes schema.sql automatically. Extracts both tables and views. AUTO_INCREMENT=N is stripped to avoid noisy git diffs. View DDL is normalized to CREATE OR REPLACE VIEW (stripping DEFINER, ALGORITHM, SQL SECURITY).

# Write to the first schema: path in sqlc.yaml
php vendor/bin/sqlc-php --generate-schema sqlc.yaml

# Write to a custom path
php vendor/bin/sqlc-php --generate-schema --schema-output=database/schema.sql sqlc.yaml
Keep the schema complete. Every table referenced in any query — including JOINed tables — must appear in the schema. Missing tables cause columns to resolve as mixed, which silently suppresses where* methods in @searchable Criteria classes. When in doubt, regenerate the schema from the live database.

Typical workflow

# 1. Pull schema from live DB
php vendor/bin/sqlc-php --generate-schema sqlc.yaml

# 2. Generate PHP classes
php vendor/bin/sqlc-php sqlc.yaml

database: block

database:
  dsn:      "mysql:host=localhost;dbname=myapp;charset=utf8mb4"
  username: "${DB_USER}"
  password: "${DB_PASS}"

  # Tables
  exclude_tables: [migrations, failed_jobs, sessions]
  # include_tables: [users, orders]    # whitelist — only extract these

  # Views — extracted by default alongside tables
  exclude_views: [v_legacy_report]
  # include_views: [v_active_users]    # whitelist — only these views

Shared CTEs

Declare reusable named CTEs in dedicated .sql files and reference them from any query with @use. sqlc-php injects the WITH name AS (...) clause before analysis — fully transparent to the Analyzer.

CTE file format

-- database/ctes/users.sql

-- @cte active_users
SELECT id, email, role, created_at
FROM users
WHERE active = 1 AND role = 'client';

-- @cte active_admins
SELECT id, email FROM users
WHERE active = 1 AND role IN ('admin', 'superadmin');

Register in sqlc.yaml

ctes:                              # global — available to every target
  - database/ctes/users.sql
  - database/ctes/orders.sql

targets:
  - namespace: App\Reports
    ctes:                          # per-target — merged with global
      - database/ctes/billing.sql

Usage in queries

-- @name ListActiveOrders
-- @class Orders
-- @returns :many
-- @use active_users
SELECT orders.* FROM orders
INNER JOIN active_users ON active_users.id = orders.user_id;

-- Multiple CTEs: comma-separated or multiple @use lines
-- @use active_users, recent_orders
CTE names must be unique across all loaded files. A query using @use must not also declare an inline WITH clause.

Annotations — quick reference

Every query needs at minimum @name and @returns. Annotations appear as SQL comments immediately before the query SQL, in any order.

AnnotationRequiredDescription
@nameYesPHP method name (camelCase)
@returnsYesReturn type — :many :one :opt :exec :cursor :paginator :batch :transaction. Legacy: :many-paginated :paginated (deprecated).
@classNoQuery class group name — inferred from table name when absent. @group is the deprecated alias.
@commentNoDescription added to the generated method docblock before @param / @return. Multiple lines supported.
@paramNoUnified input parameter annotation. @param name table.col (type hint), @param name ?string (nullable), @param name ?string:optional (nullable + skippable WHERE). Replaces @optional and @nullable.
@partialNoQuery-level flag for UPDATE statements. Params wrapped in COALESCE(:p, col) become nullable — passing null preserves the existing column value instead of updating it. Requires COALESCE in the SQL. See comparison with @param ?type in the @partial section.
@returningNoAfter an INSERT, fetch and return the created row by lastInsertId(). Only for :one INSERT.
@dtoNoOverride the auto-generated result DTO class name.
@columnNoRename a result column in the DTO without using SQL AS.
@embedNoGroup prefixed columns from a JOIN into a nested readonly object.
@typeNoUniversal column type override. Scalar: @type col float / @type col ?float. JSON DTO: @type col json:City[] / @type col ?json:City. Covers all cases previously handled by @json and @nillable.
@filterNoGenerate typed where* methods in the Criteria for JOIN columns not in the SELECT list. Table prefix always applied: @filter accounts.email → whereAccountsEmailEq(). Use accounts.* for all columns of a table.
@withNoQuery capability extensions: criteria — typed Criteria. count — Count(): int. exists — Exists(): bool. returning — fetch row after INSERT. paginated — ?$limit/$offset params. Combinable: @with criteria, paginated, count.
@cursorNoDeclare cursor columns for keyset pagination. Required with :cursor. Supports table.col qualified names.
@useNoInject shared CTEs from ctes: files as a WITH clause.
@deprecatedNoEmit @deprecated in the generated method docblock.
@callsNoMethods to call in sequence — used with :transaction.
@paramNoExplicit table.column type annotation for an ambiguous named parameter.

@name

Sets the PHP method name. Use camelCase by convention. The name is used verbatim — sqlc-php does not transform it.

-- @name GetUserById
-- @class Users
-- @returns :one
SELECT * FROM users WHERE id = :id;

Generates: public function getUserById(int $id): User

@class

Groups queries into the same generated file. Multiple queries with the same @class value produce one Query class. When omitted, the group is inferred from the FROM table name.

-- @name ListActive
-- @class User
-- @returns :many
SELECT * FROM users WHERE active = 1;

-- @name GetById
-- @class User        ← same class → same UserQuery.php
-- @returns :opt
SELECT * FROM users WHERE id = :id;
@group is the deprecated predecessor of @class — it still works but emits a warning to stderr.

@returns

Declares the return type of the generated method. See the Return Types section for full details on each type.

-- @returns :many            → array of typed objects
-- @returns :one             → single typed object (throws if not found)
-- @returns :opt             → single typed object or null
-- @returns :exec            → void (INSERT / UPDATE / DELETE)
-- @returns :paginator      → PaginatedResult (items + total + page metadata)
-- @returns :cursor          → CursorResult (keyset pagination)
-- @returns :batch           → run the same query N times in one transaction
-- @returns :transaction     → call multiple methods in one transaction

@comment v2.14.0

Adds a human-readable description to the generated PHP method's docblock, placed before the @param and @return tags. Multiple @comment lines are each rendered as a separate line in the description. Position-independent — can appear before or after @name.

-- @name GetActiveUser
-- @class Users
-- @returns :opt
-- @comment Returns the active user matching the given ID.
-- @comment Returns null when no user is found or the user is inactive.
SELECT * FROM users WHERE id = :id AND active = 1;
// Generated docblock:
/**
 * Returns the active user matching the given ID.
 * Returns null when no user is found or the user is inactive.
 *
 * @param int $id
 * @return User|null
 */
public function getActiveUser(int $id): ?User
Combine @comment with @deprecated to explain why a method is deprecated and what to use instead.

@param — unified input parameter annotation v2.17.0 unified

@param is the single annotation for configuring input parameters. It covers all cases — type hints, nullable types, and optional (skippable) WHERE conditions — using one consistent syntax.

SyntaxPHP typeSQL rewriteUse case
@param name table.colFrom schemaNoExplicit type hint — resolve from table.col in schema
@param name phpTypephpTypeNoExplicit PHP type (e.g. int, string, float)
@param name ?phpType?phpTypeNoNullable — passes null to set the column to NULL
@param name phpType:optional?phpType(:p_chk IS NULL OR col OP :p)Optional WHERE filter — null skips the condition
@param name ?phpType:optional?phpTypeSame as aboveExplicit nullable + optional (equivalent to phpType:optional)

Nullable param — SET column to NULL

Use ?phpType when the column accepts NULL and you want to allow the caller to pass null. The SQL is unchanged — null is bound to PDO and sets the column to NULL.

-- @name UpdateUserProfile
-- @class Users
-- @returns :exec
-- @comment Set avatar and deletion timestamp. Pass null to clear either.
-- @param avatarUrl ?string
-- @param deletedAt ?string
UPDATE users
SET avatar_url = :avatarUrl,
    deleted_at = :deletedAt
WHERE id = :id;
public function updateUserProfile(
    ?string $avatarUrl,   // null → sets avatar_url to NULL
    ?string $deletedAt,   // null → sets deleted_at to NULL
    int     $id,
): void

// Clear avatar:
$query->updateUserProfile(avatarUrl: null, deletedAt: null, id: 1);

// Set avatar:
$query->updateUserProfile(avatarUrl: 'https://cdn.example.com/1.jpg', deletedAt: null, id: 1);

Optional param — skip WHERE condition

Use ?phpType:optional when the parameter is an optional WHERE filter — passing null omits the condition entirely. The SQL is rewritten at compile time to (:p_chk IS NULL OR col OP :p).

-- @name ListUsers
-- @class Users
-- @returns :many
-- @param role   ?string:optional
-- @param active ?int:optional
SELECT * FROM users WHERE role = :role AND active = :active;
public function listUsers(
    ?string $role   = null,   // null → condition skipped entirely
    ?int    $active = null,   // null → condition skipped entirely
): array

// All users:
$query->listUsers();

// Active clients only:
$query->listUsers(role: 'client', active: 1);

// All active users regardless of role:
$query->listUsers(active: 1);

Type hint — resolve from schema

When the resolver cannot determine the correct type automatically (typically with ambiguous JOIN params), use the table.col syntax to pin the type to a specific schema column.

-- @name GetOrderByUser
-- @class Orders
-- @returns :opt
-- @param userId users.id     ← explicit: :userId is users.id type (int)
SELECT * FROM orders
JOIN users ON users.id = orders.user_id
WHERE orders.user_id = :userId;

Explicit PHP type

When the resolved type is wrong and you want to specify the exact PHP type without a schema hint, use a plain PHP type name.

-- @param total  float   ← force float even if schema says DECIMAL
-- @param count  int
-- @param label  string
Disambiguation rule: if the second token contains a . it is a table.col type hint (legacy). Otherwise it is a PHP type with optional :optional modifier. Both forms can coexist in the same query.
Difference between ?phpType, ?phpType:optional, and @partial:

@param col ?string — passes null to PDO; sets the column to NULL in the database.
@param col ?string:optional — skips the WHERE condition entirely when null.
@partial (query-level) — preserves the existing column value when null, via COALESCE(:p, col) in the SET clause.

See @partial for the full comparison table.

@filter v2.19.4

Generates typed where* filter methods in the Criteria class for JOIN columns that are not in the SELECT list. Without @filter, the only way to filter on JOIN columns is andRawCondition() — which gives up type safety and IDE autocompletion.

Methods generated by @filter always carry the table name as a prefix to avoid collision with SELECT-derived methods:

SyntaxGenerates methods for
@filter accounts.emailSpecific column — whereAccountsEmailEq(), whereAccountsEmailLike(), etc.
@filter accounts.*All columns of the accounts table
@filter accounts.email, accounts.passwordMultiple specific columns in one line

Example — specific columns

-- @name ListProfiles
-- @class Profile
-- @returns :cursor
-- @cursor profiles.id DESC
-- @with criteria
-- @filter accounts.password     ← generates whereAccountsPasswordIsNull/IsNotNull
-- @filter accounts.google_id    ← generates whereAccountsGoogleIdIsNull/IsNotNull
-- @filter reserve.status        ← generates whereReserveStatusEq, In, etc.
SELECT
    profiles.id,
    profiles.firstname,
    profiles.lastname,
    accounts.email
FROM profiles
INNER JOIN accounts ON accounts.profile_id = profiles.id
LEFT JOIN reserve ON reserve.profile_id = profiles.id
WHERE (accounts.password IS NOT NULL OR accounts.google_id IS NOT NULL)
GROUP BY profiles.id
ORDER BY profiles.id DESC;
// Generated Criteria — SELECT columns + @filter columns:
$criteria = (new ListProfilesCriteria())
    ->whereFirstnameLike('alice')               // from SELECT
    ->whereEmailEq('alice@example.com')         // from SELECT (accounts.email)
    ->whereAccountsPasswordIsNotNull()           // from @filter accounts.password
    ->whereAccountsGoogleIdIsNull()             // from @filter accounts.google_id
    ->whereReserveStatusEq('confirmed');         // from @filter reserve.status

$result = $query->listProfiles(criteria: $criteria);

Example — wildcard (all columns of a table)

-- @with criteria
-- @filter accounts.*     ← generates where* for every column in accounts
SELECT profiles.id, profiles.firstname FROM profiles
INNER JOIN accounts ON accounts.profile_id = profiles.id;
// All accounts columns available as prefixed filter methods:
$criteria = (new ListProfilesCriteria())
    ->whereAccountsEmailEq('alice@example.com')
    ->whereAccountsPasswordIsNull()
    ->whereAccountsActiveEq(1);
Method naming — always table-prefixed. @filter accounts.email → whereAccountsEmailEq(), never whereEmailEq(). This means no collision with SELECT-derived methods even when the column name is the same (e.g. accounts.email is in the SELECT → whereEmailEq() from SELECT, whereAccountsEmailEq() from @filter).
All @filter tables must be in the schema. Type resolution for @filter columns uses the schema catalog. If the table or column is missing, the generator throws a fatal error that stops compilation: 
sqlc-php: @filter 'accounts.ghost' — column 'ghost' not found in table 'accounts'.
Available columns: id, profile_id, email, password, google_id, active.
Run --generate-schema to extract the full schema from the live database.

@partial

A query-level flag for UPDATE statements where some columns should only be updated when a value is explicitly provided. Passing null for a partial param leaves the column unchanged — the existing database value is preserved via COALESCE.

Only valid on :exec UPDATE queries. The SQL must use COALESCE(:param, col) for each partial column — sqlc-php detects the partial params by scanning for this pattern in the SET clause.

-- @name UpdateUserProfile
-- @class Users
-- @returns :exec
-- @partial
UPDATE users
SET name      = COALESCE(:name,      name),
    email     = COALESCE(:email,     email),
    avatar_url = COALESCE(:avatarUrl, avatar_url)
WHERE id = :id;
// Generated signature — all partial params are nullable with default null:
public function updateUserProfile(
    ?string $name      = null,
    ?string $email     = null,
    ?string $avatarUrl = null,
    int     $id,
): void

// Update only the email — name and avatar_url are left unchanged:
$query->updateUserProfile(email: 'new@example.com', id: 1);

// Update all three fields:
$query->updateUserProfile(name: 'Alice', email: 'alice@x.com', avatarUrl: '/img/a.png', id: 1);

// Set avatar_url to NULL in the database — pass a non-null sentinel (not supported via @partial).
// Use @param avatarUrl ?string for that case instead.

How it works

sqlc-php rewrites nothing — the COALESCE(:param, col) is your SQL. The analyzer scans the SET clause for the pattern, marks those params as optional = true and phpType = ?type, and generates the nullable method signature. At runtime, passing null lets MySQL's COALESCE fall back to the current column value.

Choosing the right mechanism for nullable UPDATE params

GoalMechanismSQL patternnull means
Skip updating a column @partial SET col = COALESCE(:p, col) Column keeps its current value
Set a column to NULL @param p ?string SET col = :p Column is set to NULL in the database
Skip a WHERE condition @param p ?string:optional WHERE col = :p → rewritten Condition is omitted entirely
@partial is a query-level flag, not a per-param modifier. It activates COALESCE detection across the entire SET clause. This is intentionally different from @param modifiers — a single -- @partial line covers all partial columns in the query, which is more ergonomic than one @param line per column for large UPDATE statements.
@partial cannot set a column to NULL — COALESCE(:p, col) will always fall back to col when :p is null. If you need both "skip update" and "set to NULL" semantics on the same column, split into two separate query methods.

@dto / @column

@dto overrides the auto-generated result DTO class name. Use it to share one DTO across multiple queries, or when the default generated name is unwieldy.

-- @name ListBillingConfig
-- @class BillingConfig
-- @dto BillingConfigRow      ← generated DTO class: BillingConfigRow.php
-- @returns :many
SELECT bc.id, bc.active, c.name AS country_name
FROM billing_config bc
JOIN countries c ON c.id = bc.country_id;

@column renames a result column in the generated DTO without adding an AS alias to the SQL:

-- @column u_email email      ← renames u_email → email in the generated DTO
SELECT id, email AS u_email FROM users WHERE id = :id;

@embed

Groups prefixed columns from a JOIN into a nested readonly object. Any columns whose alias starts with the declared prefix become properties of a separate class.

-- @name GetUserWithRole
-- @embed Role role__           ← columns prefixed "role__" → Role object
-- @returns :one
SELECT
    u.id, u.email,
    r.name AS role__name,
    r.slug AS role__slug
FROM users u
JOIN roles r ON r.id = u.role_id
WHERE u.id = :id;
readonly class GetUserWithRoleRow {
    public function __construct(
        public int    $id,
        public string $email,
        public Role   $role,   // nested object
    ) {}
}

readonly class Role {
    public function __construct(
        public string $name,
        public string $slug,
    ) {}
}

@type — universal column type override v2.16.0 unified

@type is the single annotation for overriding the PHP type of any result column. It covers all cases — scalar types, nullable types, and JSON DTO deserialization — using one consistent syntax: @type alias phpType.

Scalar and nullable types

-- @type total     float         → float
-- @type total     ?float        → float|null   (nullable)
-- @type active    bool
-- @type role      string
-- @type ids       array         → scalar JSON array (json_decode applied automatically)
-- @type label     ?string       → string|null

Use scalar @type whenever the analyzer infers the wrong type — UNION queries, constant expressions, aggregates, or IF() expressions where the true/false branches have different types.

-- @name GetDashboardStats
-- @class Stats
-- @returns :one
-- @type total_users int
-- @type revenue     float
-- @type label       string
SELECT
    COUNT(DISTINCT users.id)  AS total_users,
    SUM(orders.total)         AS revenue,
    'active'                  AS label
FROM orders JOIN users ON users.id = orders.user_id;

JSON DTO types — json:Class and json:Class[]

When a column contains JSON produced by JSON_OBJECT() or JSON_ARRAYAGG(), use json:ClassName to deserialize it into a typed readonly DTO. sqlc-php generates the DTO class automatically from the matching schema table.

SyntaxPHP typefromRow() castUse case
@type col json:City[]City[]array_map(City::fromRow, json_decode(...))Array of DTOs, non-nullable
@type col ?json:City[]City[]|nullnull check + array_mapArray of DTOs, nullable (LEFT JOIN)
@type col json:CityCityCity::fromRow(json_decode(...))Single DTO object, non-nullable
@type col ?json:CityCity|nullnull check + fromRowSingle DTO, nullable (LEFT JOIN)
 
-- @name GetCountryWithCities
-- @class Countries
-- @returns :one
-- @type cities json:City[]         ← non-nullable array of City DTOs
SELECT
    countries.id,
    countries.name,
    JSON_ARRAYAGG(
        JSON_OBJECT('id', cities.id, 'name', cities.name)
    ) AS cities
FROM countries
INNER JOIN cities ON cities.country_id = countries.id
WHERE countries.id = :id
GROUP BY countries.id;
-- @name GetOrderWithDetails
-- @class Orders
-- @returns :one
-- @type items   ?json:Item[]       ← nullable: LEFT JOIN may produce null
-- @type address ?json:Address      ← nullable: customer may have no address
SELECT
    orders.id,
    orders.total,
    JSON_ARRAYAGG(JSON_OBJECT('id', items.id, 'name', items.name, 'price', items.price)) AS items,
    JSON_OBJECT('street', addresses.street, 'city', addresses.city) AS address
FROM orders
LEFT JOIN items     ON items.order_id     = orders.id
LEFT JOIN addresses ON addresses.order_id = orders.id
WHERE orders.id = :id
GROUP BY orders.id;
// Generated DTO:
readonly class GetOrderWithDetailsRow {
    public function __construct(
        public int      $id,
        public float    $total,
        /** @var Item[]|null */
        public ?array   $items,    // null when no items (LEFT JOIN)
        public ?Address $address,  // null when no address (LEFT JOIN)
    ) {}

    public static function fromRow(array $row): self {
        return new self(
            id:      (int) $row['id'],
            total:   (float) $row['total'],
            items:   isset($row['items']) && $row['items'] !== null
                         ? array_map(fn($r) => Item::fromRow($r), json_decode($row['items'], true) ?? [])
                         : null,
            address: isset($row['address']) && $row['address'] !== null
                         ? Address::fromRow(json_decode($row['address'], true) ?? [])
                         : null,
        );
    }
}

Scalar JSON arrays — @type col array

For JSON_ARRAYAGG of scalar values (IDs, strings), use @type col array. The json_decode cast is applied automatically for any column typed as array.

-- @type reserves array
SELECT orders.id, JSON_ARRAYAGG(reserve.id) AS reserves
FROM orders LEFT JOIN reserve ON reserve.order_id = orders.id
WHERE orders.id = :id GROUP BY orders.id;
public array $reserves,
// fromRow: json_decode((string) $row['reserves'], true) ?? []
// Result: [1, 2, 3, 4]  — array of int IDs
Position-independent. @type can appear before or after @name. Multiple @type lines are supported — one per column.

@with — query capability extensions v2.18.0

Declares additional capabilities for a query. One annotation replaces multiple — modifiers are comma-separated and order-independent.

ModifierGeneratesValid with
criteriaTyped XxxCriteria class + $criteria param on the method:many :paginator :cursor

criteria — dynamic WHERE filters

-- @name ListOrders
-- @class Orders
-- @returns :many
-- @with criteria
SELECT orders.id, orders.status, orders.total, orders.created_at
FROM orders
WHERE user_id = :userId;
// Generated: ListOrdersCriteria.php  ← named after @name, not @class
$criteria = (new ListOrdersCriteria())
    ->whereStatusEq('pending')
    ->whereTotalGte(100.0)
    ->orderByCreatedAt('DESC');

$orders = $query->listOrders(userId: 1, criteria: $criteria);
Criteria class names are derived from @name, not @class. @name ListOrders → ListOrdersCriteria. This guarantees uniqueness when multiple queries in the same @class group each use @with criteria — they produce distinct files rather than overwriting each other.

Example: two queries in @class Profile:
  • @name ListProfiles → ListProfilesCriteria.php
  • @name SearchProfiles → SearchProfilesCriteria.php
All tables in the query must be in the schema for where* methods to be generated. Columns from tables missing in the schema resolve to mixed and produce no filter methods. Run --generate-schema to extract the full schema.

count — total row count

-- @name ListOrders
-- @class Orders
-- @returns :many
-- @with paginated, count
SELECT orders.id, orders.status FROM orders WHERE user_id = :userId
ORDER BY created_at DESC;
// Generated: listOrdersCount() companion method
$total  = $query->listOrdersCount(userId: 1);
$orders = $query->listOrders(userId: 1, limit: 20, offset: 0);

exists — presence check

Generates a {name}Exists(): bool method using SELECT EXISTS(SELECT 1 FROM (...) AS _exists_subquery) — the database stops scanning at the first matching row, making it more efficient than COUNT(*) > 0.

-- @name ListOrders
-- @class Orders
-- @returns :many
-- @with exists
SELECT orders.id FROM orders WHERE user_id = :userId;
// Generated: listOrdersExists() companion method
if ($query->listOrdersExists(userId: 1)) {
    // user has at least one order
}

paginated — LIMIT / OFFSET params v2.19.2

Adds ?int $limit = null and int $offset = 0 parameters and auto-injects LIMIT :limit OFFSET :offset into the SQL. When $limit is null, no LIMIT is applied and all rows are returned. Replaces :many-paginated.

-- @name ListOrders
-- @class Orders
-- @returns :many
-- @with paginated
SELECT orders.id, orders.status, orders.total
FROM orders
WHERE user_id = :userId
ORDER BY created_at DESC;
// Generated signature:
public function listOrders(int $userId, ?int $limit = null, int $offset = 0): array

// All rows:
$all    = $query->listOrders(userId: 1);

// Page 2 (20 per page):
$page2  = $query->listOrders(userId: 1, limit: 20, offset: 20);

Combine with count for pagination UI:

-- @with paginated, count, criteria
$criteria = (new ListOrdersCriteria())->whereStatusEq('pending');
$total  = $query->listOrdersCount(criteria: $criteria);
$orders = $query->listOrders(criteria: $criteria, limit: 20, offset: 0);
:many-paginated is deprecated since v2.19.2. It still works but emits a stderr deprecation warning. Replace with -- @returns :many + -- @with paginated.

returning — fetch created row after INSERT

After an INSERT, fetches and returns the newly created row using lastInsertId(). Only valid on :one INSERT queries.

-- @name CreateUser
-- @class Users
-- @returns :one
-- @with returning
INSERT INTO users (email, name, active) VALUES (:email, :name, 1);
// Inserts and immediately returns the full hydrated User object
$user = $query->createUser(email: 'alice@example.com', name: 'Alice');
echo $user->id;   // the auto-increment ID

criteria + exists — check before paginating

When criteria and exists are both active, Exists() accepts the same $criteria parameter — check existence under the same filters before paginating.

@cursor v2.11.2

Declares the cursor columns for keyset (cursor-based) pagination. Required when using :cursor. Supports qualified table.column names to disambiguate JOINs. Multiple columns produce a compound cursor.

-- @name ListOrders
-- @class Orders
-- @returns :cursor
-- @cursor created_at DESC, id DESC    ← single or compound cursor
SELECT orders.id, orders.total, orders.created_at
FROM orders
WHERE user_id = :userId
ORDER BY orders.created_at DESC, orders.id DESC;
-- For GROUP BY queries with JOIN ambiguity, use qualified names:
-- @cursor profile_reserve.created_at DESC, profile_reserve.profile_id DESC
// First page
$result = $query->listOrders(userId: 1, limit: 20);

// Next page
$result = $query->listOrders(userId: 1, after: $result->nextCursor, limit: 20);

// Previous page
$result = $query->listOrders(userId: 1, before: $result->prevCursor, limit: 20);

// CursorResult properties:
// $result->items       — array of typed objects
// $result->hasMore     — more pages forward
// $result->hasPrev     — more pages backward
// $result->nextCursor  — opaque token for next page
// $result->prevCursor  — opaque token for previous page

@use v2.13.0

References one or more shared CTEs declared in ctes: files. sqlc-php injects the WITH name AS (...) clause before the query SQL, transparent to the Analyzer.

-- @name ListActiveUserOrders
-- @class Orders

-- @use active_users
SELECT orders.* FROM orders
INNER JOIN active_users ON active_users.id = orders.user_id;

-- Multiple CTEs — comma-separated or separate lines
-- @use active_users, recent_orders
-- @use billing_summary

Used with :transaction to declare which methods are called inside a single database transaction. All calls share the same PDO connection in autocommit: false mode.

Return types

:many — array of rows

Returns all matching rows as a PHP array of typed objects. No LIMIT is applied unless you write one in the SQL.

-- @name ListActiveUsers
-- @class Users
-- @returns :many
SELECT * FROM users WHERE active = 1 ORDER BY name;
/** @return User[] */
public function listActiveUsers(): array

:paginator — PaginatedResult with metadata

Returns a PaginatedResult object with items, total, perPage, currentPage, and lastPage — everything a pagination UI needs in one call. The total count is computed automatically via a companion SELECT COUNT(*).

-- @name ListProductsPaginated
-- @class Products
-- @returns :paginator
SELECT products.id, products.name, products.price FROM products ORDER BY name;
public function listProductsPaginated(int $limit = 10, int $offset = 0): PaginatedResult

// PaginatedResult properties:
// $result->items       — array of typed objects
// $result->total       — total matching rows
// $result->perPage     — rows per page
// $result->currentPage — current page number (1-indexed)
// $result->lastPage    — last page number
Difference from :many + @with paginated: :paginator returns a rich PaginatedResult object with total and page metadata computed automatically. :many + @with paginated returns a plain array — you manage the count separately via @with count.

:cursor — keyset pagination

Implements cursor-based (keyset) pagination — O(1) regardless of page depth, unlike OFFSET which degrades on large datasets. Requires @cursor to declare the sort columns. Combine with @searchable for dynamic filters and @counted for totals.

-- @name ListOrders
-- @class Orders
-- @returns :cursor
-- @cursor created_at DESC, id DESC
-- @searchable
-- @counted
SELECT orders.id, orders.total, orders.status, orders.created_at
FROM orders
WHERE user_id = :userId
ORDER BY orders.created_at DESC, orders.id DESC;
public function listOrders(
    int    $userId,
    ?OrdersCriteria $criteria = null,
    ?string $after  = null,
    ?string $before = null,
    int    $limit   = 20,
): CursorResult

public function listOrdersCount(int $userId, ?OrdersCriteria $criteria = null): int

:one — single row, throws if not found

Returns exactly one typed object. Throws a RuntimeException if the query returns no rows. Use :opt when zero results is a valid case.

-- @name GetUser
-- @class Users
-- @returns :one
SELECT * FROM users WHERE id = :id;
public function getUser(int $id): User   // throws if not found

:opt — single row or null

Returns one typed object or null when no row matches. The most common return type for "find by ID" queries.

-- @name FindUserByEmail
-- @class Users
-- @returns :opt
SELECT * FROM users WHERE email = :email AND active = 1;
public function findUserByEmail(string $email): ?User

:exec — INSERT / UPDATE / DELETE

Returns void. Use for any query that modifies data without needing a return value. Combine with @with returning on INSERT queries when you need the created row.

-- @name UpdateUserName
-- @class Users
-- @returns :exec
UPDATE users SET name = :name WHERE id = :id;

-- @name DeleteUser
-- @class Users
-- @returns :exec
DELETE FROM users WHERE id = :id;

:batch — run same query N times

Runs the same query multiple times within one transaction. The generated method accepts an array of parameter arrays and returns the number of affected rows.

-- @name InsertUserBatch
-- @class Users
-- @returns :batch
INSERT INTO users (email, name) VALUES (:email, :name);
// Returns total affected rows
$affected = $query->insertUserBatch([
    ['email' => 'a@x.com', 'name' => 'Alice'],
    ['email' => 'b@x.com', 'name' => 'Bob'],
]);

:transaction — orchestrate multiple methods

Calls multiple methods inside a single database transaction. Declare the methods to call with @calls. If any throws, the transaction is rolled back.

-- @name TransferBalance
-- @class Accounts
-- @returns :transaction
-- @calls debitAccount, creditAccount
// Calls debitAccount() then creditAccount() in one transaction
$query->transferBalance(fromId: 1, toId: 2, amount: 100.00);

Criteria class

Each @with criteria query generates a typed XxxCriteria class extending the Criteria base. Criteria are immutable — every method returns a new instance.

All tables in the query must be declared in the schema for where* methods to be generated. The generator resolves column types from the schema catalog — columns from tables not in the schema resolve to mixed and produce no filter methods. Use --generate-schema to extract the full schema from the live database.

OR groups

$criteria = (new UsersCriteria())
    ->whereActiveEq(true)                                     // AND active = 1
    ->orGroup(fn($c) => $c->whereCountryIdEq(164))           // OR (country_id = 164)
    ->orGroup(fn($c) => $c->whereCountryIdEq(165));          // OR (country_id = 165)
// WHERE (active = 1) OR (country_id = 164) OR (country_id = 165)

andRawCondition() / orRawCondition() — filter on JOIN columns

Inject verbatim SQL fragments into the WHERE clause when the filter target is a JOIN column not present in the SELECT list — and therefore has no generated typed method.

MethodConnectorUse case
andRawCondition(sql, bindings)ANDMust match — narrows the result set
orRawCondition(sql, bindings)ORAlternative match — widens the result set

andRawCondition — must match (AND)

$criteria = (new ProfileReserveCriteria())
    ->whereSnapFirstnameLike('alice')
    ->andRawCondition(
        'reserve.id = :reserveId',
        [':reserveId' => [$id, PDO::PARAM_INT]]
    );

$result = $repo->listProfileReserve(criteria: $criteria);
$count  = $repo->listProfileReserveCount(criteria: $criteria);

Effective SQL: WHERE snap_firstname LIKE :snap_firstname_f0 AND reserve.id = :reserveId

orRawCondition — alternative match (OR)

// Single OR raw condition
$criteria = (new ProfileReserveCriteria())
    ->whereStatusEq('active')
    ->orRawCondition('reserve.is_legacy = 1');

// Multiple
$criteria = (new ProfileReserveCriteria())
    ->whereStatusEq('active')
    ->orRawCondition('reserve.type = :t1', [':t1' => ['vip',   PDO::PARAM_STR]])
    ->orRawCondition('reserve.type = :t2', [':t2' => ['promo', PDO::PARAM_STR]]);

Effective SQL: WHERE (status = :status_f0) OR (reserve.is_legacy = 1)

Combining both in one criteria

$criteria = (new ProfileReserveCriteria())
    ->whereSnapFirstnameLike('alice')           // AND typed filter
    ->andRawCondition('reserve.deleted_at IS NULL')  // AND raw
    ->orRawCondition('reserve.is_legacy = 1');       // OR raw
// WHERE (snap_firstname LIKE :f0 AND reserve.deleted_at IS NULL) OR (reserve.is_legacy = 1)
⚠ No SQL injection protection. Always use named placeholders — never interpolate user input directly. 
// ✅ Safe
->andRawCondition('reserve.id = :rid', [':rid' => [42, PDO::PARAM_INT]])

// ❌ Unsafe
->andRawCondition("reserve.id = {$userInput}")

fromArray() — build criteria from a filter array

Constructs a Criteria from an array of tuples — useful when filters come from a request payload or config.

$criteria = OrdersCriteria::fromArray([
    ['status',     '!=',       'cancelled'],
    ['total',      '>=',       100.0],
    ['created_at', 'between',  ['2024-01-01', '2024-12-31']],
    ['name',       'like',     'alice'],
    ['tag',        'in',       ['vip', 'premium']],
    ['deleted_at', 'is_null'],
]);

// Supported operators:
// = != <> > < >= <= eq neq gt lt gte lte
// like  starts_with  ends_with
// in  not_in
// is_null  is_not_null  null  not_null
// between

orGroup() — OR logic

// WHERE (status = 'active') OR (status = 'pending' AND role = 'admin')
$criteria = (new OrdersCriteria())
    ->whereStatusEq('active')
    ->orGroup(fn($c) => $c
        ->whereStatusEq('pending')
        ->whereRoleEq('admin')
    );

-- Dynamic filtering on grouped queries with cursor pagination
-- @name ListProfileReserve
-- @class ProfileReserve
-- @dto ProfileReserve
-- @searchable
-- @counted
-- @type reserves array
-- @cursor profile_reserve.created_at DESC, profile_reserve.profile_id DESC
-- @returns :cursor
SELECT
    profile_reserve.profile_id,
    MAX(profile_reserve.snap_firstname)  AS snap_firstname,
    MAX(profile_reserve.snap_lastname)   AS snap_lastname,
    MAX(profile_reserve.created_at)      AS created_at,
    JSON_ARRAYAGG(reserve.id)            AS reserves
FROM profile_reserve
INNER JOIN accounts ON accounts.profile_id = profile_reserve.profile_id
LEFT JOIN reserve   ON reserve.id = profile_reserve.reserve_id
WHERE accounts.password IS NOT NULL OR accounts.google_id IS NOT NULL
GROUP BY profile_reserve.profile_id
ORDER BY MAX(profile_reserve.created_at) DESC, profile_reserve.profile_id DESC;

For nullable columns (LEFT JOIN) or single objects, use the ? prefix and omit []:

-- @type cities  ?json:City[]    ← City[]|null  (LEFT JOIN may produce null)
-- @type address ?json:Address   ← Address|null (LEFT JOIN may produce null)
-- @type address  json:Address   ← Address      (INNER JOIN, always present)

For scalar arrays (array of IDs), use @type col array:

-- @type tag_ids array
SELECT orders.id, JSON_ARRAYAGG(tags.id) AS tag_ids
FROM orders JOIN tags ON tags.order_id = orders.id
WHERE orders.id = :id GROUP BY orders.id;

MySQL ENUMs

Columns defined as ENUM('a','b','c') are automatically mapped to PHP backed enums. The enum class is generated alongside the model.

-- schema.sql
CREATE TABLE orders (
    id     INT AUTO_INCREMENT PRIMARY KEY,
    status ENUM('pending','paid','cancelled','refunded') NOT NULL
);
// Generated: OrderStatus.php
enum OrderStatus: string {
    case Pending   = 'pending';
    case Paid      = 'paid';
    case Cancelled = 'cancelled';
    case Refunded  = 'refunded';
}

// Generated model uses it:
readonly class Order {
    public function __construct(
        public int         $id,
        public OrderStatus $status,
    ) {}
}

// Usage:
$order = $query->getOrder(id: 1);
if ($order->status === OrderStatus::Paid) { ... }

UNION queries

UNION / UNION ALL queries are supported. sqlc-php resolves each branch independently and merges types: same type + one nullable → nullable; different types → mixed. Use @type for manual corrections.

-- @name ListAllStaff
-- @class Staff
-- @returns :many
-- @type score int           ← override: both branches have int score, one nullable
SELECT id, email, score, 'user'  AS role FROM users  WHERE active = 1
UNION ALL
SELECT id, email, score, 'admin' AS role FROM admins WHERE active = 1;

Cursor pagination with GROUP BY

When using cursor + searchable on a GROUP BY query, the cursor condition and criteria filters are automatically injected before the GROUP BY clause — not after it — so the SQL remains valid under only_full_group_by.

-- @name ListSummary
-- @class Summary
-- @searchable
-- @counted
-- @cursor orders.created_at DESC, orders.user_id DESC
-- @returns :cursor
SELECT
    orders.user_id,
    COUNT(*) AS order_count,
    SUM(orders.total) AS revenue,
    MAX(orders.created_at) AS created_at
FROM orders
WHERE orders.status != 'cancelled'
GROUP BY orders.user_id
ORDER BY MAX(orders.created_at) DESC, orders.user_id DESC;

The effective runtime SQL (after criteria and cursor injection):

SELECT ...
FROM orders
WHERE orders.status != 'cancelled'
AND snap_firstname LIKE :snap_firstname_f0    ← criteria — before GROUP BY ✓
AND (:__cursor_chk IS NULL OR ...)            ← cursor — before GROUP BY ✓
GROUP BY orders.user_id
ORDER BY MAX(orders.created_at) DESC, orders.user_id DESC
LIMIT 21

Model class

One model per schema table. Readonly, PHP 8.3+ constructor promotion. The fromRow() static method handles all type casts (int, float, bool, DateTimeImmutable, enum, json_decode).

// Generated: User.php
declare(strict_types=1);

namespace App\Database;

readonly class User
{
    public function __construct(
        public int                  $id,
        public string               $email,
        public string               $name,
        public bool                 $active,
        public \DateTimeImmutable   $createdAt,
        public ?string              $deletedAt,
    ) {}

    public static function fromRow(array $row): self
    {
        return new self(
            id:        (int)    $row['id'],
            email:     (string) $row['email'],
            name:      (string) $row['name'],
            active:    (bool)   $row['active'],
            createdAt: new \DateTimeImmutable((string) $row['created_at']),
            deletedAt: isset($row['deleted_at']) ? (string) $row['deleted_at'] : null,
        );
    }
}

Interface

A matching interface is generated for every query class, enabling mock-based testing and container binding.

// Generated: UserQueryInterface.php
interface UserQueryInterface
{
    public function getUser(int $id): ?User;
    public function listActiveUsers(): array;
    public function createUser(string $email, string $name): User;
}

Extension trait

Define an extensions: block in sqlc.yaml to inject custom methods via a trait. The generated class uses the trait automatically. Useful for adding higher-level methods that compose multiple queries.

targets:
  - namespace: "App\\Database"
    extensions:
      - trait:  "App\\Database\\UserQueryExtension"
        file:   "generated/UserQueryExtension.php"
// UserQueryExtension.php (you write this)
trait UserQueryExtension
{
    public function findOrFail(int $id): User
    {
        $user = $this->getUser($id);
        if ($user === null) throw new NotFoundException("User {$id} not found");
        return $user;
    }
}

Integration

Basic usage

$pdo   = new PDO('mysql:host=localhost;dbname=myapp;charset=utf8mb4', $user, $pass);
$pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
$pdo->setAttribute(PDO::ATTR_EMULATE_PREPARES, false);   // recommended

$query = new UserQuery($pdo);

// Fetch one
$user = $query->getUser(id: 1);

// Fetch many
$users = $query->listActiveUsers();

// Paginate
$orders = $query->listOrders(userId: 1, limit: 20, offset: 0);

// Dynamic criteria
$criteria = (new UsersCriteria())->whereEmailLike('alice')->orderByCreatedAt('DESC');
$users = $query->listUsers(criteria: $criteria);
Set PDO::ATTR_EMULATE_PREPARES = false to let MySQL parse named placeholders natively. This avoids issues with SQL containing string literals like JSON_OBJECT('key', col) near named params.

lastQuery() and query logging

Every generated query class tracks the most recently executed query in $this->lastQuery — a QueryObject with the SQL, bindings, method name, and execution duration. Use the PSR-3 logger or $afterQuery hook for observability.

// PSR-3 logger — logs every query at DEBUG level
$query = new UserQuery($pdo, logger: $logger);

// afterQuery hook — integrate with Debugbar, metrics, etc.
$query = new UserQuery($pdo, afterQuery: function (QueryObject $q): void {
    echo "[{$q->duration}ms] {$q->name}: {$q->sql}";
});

// Access after each call
$query->getUser(id: 1);
$last = $query->lastQuery();
// $last->sql       — the SQL string
// $last->bindings  — bound values
// $last->name      — method name
// $last->duration  — execution time in ms

Laravel integration

Bind generated interfaces in a service provider and inject them into controllers and jobs via the container.

// app/Providers/DatabaseServiceProvider.php
class DatabaseServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->app->singleton(UserQueryInterface::class, function (Application $app) {
            $pdo = DB::connection()->getPdo();
            return new UserQuery($pdo, logger: $app->make(LoggerInterface::class));
        });

        $this->app->singleton(OrderQueryInterface::class, function (Application $app) {
            return new OrderQuery(DB::connection()->getPdo());
        });
    }
}
// app/Http/Controllers/UserController.php
class UserController extends Controller
{
    public function __construct(
        private readonly UserQueryInterface $users,
    ) {}

    public function show(int $id): JsonResponse
    {
        $user = $this->users->getUser(id: $id);
        abort_if($user === null, 404);
        return response()->json($user);
    }

    public function index(Request $request): JsonResponse
    {
        $criteria = (new UsersCriteria())
            ->whereActiveEq(true);

        if ($request->filled('email')) {
            $criteria = $criteria->whereEmailLike($request->input('email'));
        }

        return response()->json($this->users->listUsers(criteria: $criteria));
    }
}

Testing

Generated interfaces make mock-based testing straightforward. Use PHPUnit mocks or any PSR-compatible test double library.

// Unit test — mock the interface
class UserServiceTest extends TestCase
{
    public function test_returns_active_users_only(): void
    {
        $mock = $this->createMock(UserQueryInterface::class);
        $mock->expects($this->once())
             ->method('listActiveUsers')
             ->willReturn([
                 new User(id: 1, email: 'alice@example.com', name: 'Alice', active: true),
             ]);

        $service = new UserService($mock);
        $result  = $service->getActiveUsers();

        $this->assertCount(1, $result);
        $this->assertSame('alice@example.com', $result[0]->email);
    }
}

class UserQueryTest extends TestCase

Changelog

v2.17.1 — andRawCondition() / orRawCondition() replace addRawCondition() feature
  • addRawCondition() removed — replaced by two explicit methods.
  • andRawCondition(sql, bindings) — injects the condition AND-ed with typed filters. Narrows the result set.
  • orRawCondition(sql, bindings) — injects the condition OR-ed against the rest of the WHERE clause. Widens the result set. The raw condition is automatically parenthesized.
  • Both methods are immutable (return a new instance) and support named placeholder bindings.
v2.17.0 — @param unified: type hint + nullable + optional in one annotation feature
  • @param name ?phpType — nullable param. Passes null to set the column to NULL. Replaces @nullable.
  • @param name ?phpType:optional — nullable + optional WHERE filter. Passing null skips the condition entirely. Replaces @optional.
  • @param name phpType — explicit PHP type override (e.g. int, float, string).
  • @param name table.col — legacy type hint from schema, unchanged.
  • @optional and @nullable deprecated — both still work but emit a stderr warning with the exact @param replacement.
  • Disambiguation rule: if the second token contains a . it is a legacy table.col hint; otherwise it is a PHP type with optional :optional modifier.
v2.16.0 — @type unified: scalar + JSON DTO + nullable feature
  • @type col json:City[] — array of City DTOs (non-nullable). Replaces @json cities City.
  • @type col ?json:City[] — City[]|null. For LEFT JOINs that may produce no rows.
  • @type col json:City — single City object (non-nullable). Replaces @json:one address City.
  • @type col ?json:City — City|null. Nullable single DTO object.
  • @type col ?phpType — nullable scalar. Replaces @nillable col.
  • @json and @nillable deprecated — both still work but emit a stderr deprecation warning with the exact @type replacement.
  • @type is now the single annotation for all result column type overrides: scalar, JSON DTO, and nullable.
v2.15.4 — Criteria::addRawCondition() feature
  • Introduced raw SQL condition support in Criteria. Superseded in v2.17.1 by andRawCondition() and orRawCondition().
v2.15.3 — Hotfix: criteria after GROUP BY in searchable/count methods hotfix
  • Fixed renderCursorCountMethod and buildSearchableSqlBlock — criteria filters were appended after GROUP BY, producing invalid SQL under only_full_group_by.
v2.15.2 — Hotfix: cursor condition after GROUP BY hotfix
  • Fixed buildCursorSql and searchable cursor SQL assembly — cursor condition was appended after GROUP BY instead of before it.
v2.15.1 — Hotfix: @cursor with table.column failed to parse hotfix
  • Parser regex \w+ rejected dots — profile_reserve.created_at produced an empty cursor array. Each cursor column now stores col (SQL ref, with dot) and key (PHP identifier, without dot).
v2.15.0 — @nullable params + typed UNION ALL merging feature
  • @nullable paramName — forces PHP param type to ?type without rewriting SQL. For UPDATE SET nullable column patterns.
